# 仓库扫码分卡板（本地离线 · 手机优先）

一个**只在本地运行、不上传任何数据**的网页程序，用于仓库「扫码建卡板」和「按货单配卡板」。  
手机浏览器打开即用，摄像头连续扫码，数据保存在手机本机（IndexedDB），刷新、关掉浏览器都不丢。

- 模式一：扫码建卡板（**卡板 → 箱子 → 条码**：每加一箱先扫型号 → 扫箱内条码 → 封箱 → 一板 50~60 箱后封板 → 导出 Excel）
- 模式二：按货单配卡板（导入货单 + 模式一 Excel → 按条码归板 → 数量多的放底层 → 导出配货表）
- 数据/导出：总表、单板表、配货表、JSON 备份与恢复、清空（二次确认）
- 设置：每板箱数上限 50/55/60、每层箱数、提示音/震动、屏幕常亮、摄像头选择

## 一、快速开始

```bash
# 1. 安装依赖（Node.js 18+，建议 20 或 22）
npm install

# 2. 生成本地 HTTPS 证书（手机用摄像头必须 https；纯电脑调试可跳过）
npm run cert

# 3. 启动（默认 https://localhost:5173，并监听局域网 IP）
npm run dev
```

启动后终端会打印地址，例如：

```
➜  Local:   https://localhost:5173/
➜  Network: https://192.168.0.59:5173/     <- 手机用这个
```

**手机访问步骤**

1. 手机和电脑连**同一个 Wi-Fi**（注意：访客网络/AP 隔离会连不上）。
2. 手机浏览器（推荐 Chrome / Edge / 夸克）打开 `https://192.168.0.59:5173`（换成你电脑的 IP）。
3. 首次提示「证书不受信任」→ 点「高级 / 继续前往」（自签证书属正常现象）。
4. 浏览器询问摄像头权限 → 选择「允许」。
5. 建议「添加到主屏幕」，之后像 App 一样打开，全屏无地址栏。

电脑端 IP 可以用 `ipconfig` 查看（IPv4 地址）。Windows 防火墙首次会弹窗，请允许 Node.js 的**专用网络**访问。

## 三、摄像头与 HTTPS 说明

浏览器规定：`getUserMedia`（摄像头）只在**安全上下文**可用，即 `https://` 或 `localhost`。  
手机通过局域网 IP 访问属于不安全上下文，**必须用 https**，否则扫码按钮会提示无法调用摄像头。

程序提供三种方案，按推荐顺序：

### 方案 A：自签证书（离线，最快）

```bash
npm run cert      # 生成 certs/cert.pem + certs/key.pem，包含 localhost 与所有局域网 IP
npm run dev
```

手机首次访问点「高级 → 继续前往」即可。缺点是每次换 IP 或清空证书后要重新确认一次。

### 方案 B：mkcert（手机不报警告，需要联网下载工具）

```bash
# Windows: choco install mkcert
mkcert -install
mkcert -cert-file certs/cert.pem -key-file certs/key.pem 192.168.0.59 localhost 127.0.0.1
npm run dev
```

把 `192.168.0.59` 换成你电脑的局域网 IP。若手机仍警告，需要把 mkcert 的根证书（`mkcert -CAROOT` 目录下的  
`rootCA.pem`）安装到手机：Android「设置 → 安全 → 加密与凭据 → 安装证书 → CA 证书」。

### 方案 C：环境变量指定证书

```bash
# PowerShell
$env:SSL_CERT="D:\certs\cert.pem"; $env:SSL_KEY="D:\certs\key.pem"; npm run dev
```

> 若三个方案都没配置，程序会自动降级为 HTTP 启动（不会卡住），此时只有电脑本机的 `localhost` 能用摄像头。  
> 想在手机上调试却又不想折腾证书，可以用 Chrome 的 `chrome://flags/#unsafely-treat-insecure-origin-as-secure`  
> 把 `http://192.168.x.x:5173` 加进白名单（仅调试用，重启浏览器失效）。

**权限排查清单**

| 现象             | 处理                                                           |
| -------------- | ------------------------------------------------------------ |
| 提示「当前不是安全上下文」  | 地址栏必须是 `https://` 开头，不能用 `http://192.168...`                 |
| 提示「摄像头权限被拒绝」   | 地址栏左侧锁图标 → 网站设置 → 摄像头 → 允许；iOS 还需在「设置 → Safari → 相机」放行       |
| 提示「摄像头被其他应用占用」 | 关掉相机、微信视频、扫码 App 等占用摄像头的程序                                   |
| 一直显示「正在启动摄像头…」 | 换 Chrome；确认没开省电模式限制后台摄像头                                     |
| 扫描识别慢          | 设置里把「每层箱数/防重复间隔」按需调整；保证光线充足，条码别反光；识别引擎会显示是「原生识别」还是「ZXing 识别」 |

## 五、数据模型

```ts
Task    { id, name, createdAt, updatedAt, status: 'scanning'|'finished',
          maxBoxesPerPallet (每板箱数上限，默认 60), pallets: Pallet[], __prefix }
Pallet  { id, taskId, code ('P001'), index, status: 'scanning'|'sealed',
          boxes: Box[], totalBoxes (= 箱数), totalBarcodes, createdAt, sealedAt? }
Box     { id, palletId, code ('B001'), index, status: 'scanning'|'sealed', model (型号),
          barcodes: Barcode[], totalBarcodes, createdAt, sealedAt?, note? }
Barcode { id, code (条码/编号，箱内唯一), index (箱内第几条), scannedAt, seq, note?, status }
OrderItem { barcode, qty, name?, model?, remark?, orderIndex,
            matchedPalletCode?, status: 'matched'|'unmatched'|'qty_mismatch', sourceQty? }
```

存储位置：浏览器 IndexedDB，数据库名 `pallet-scan`，表 `tasks`（任务+卡板+箱+条码）与 `kv`（设置、当前任务）。  
扫码时**每次改动都会防抖写入**，切到后台/关闭页面时再强制写一次，保证刷新不丢。  
JSON 备份里的 `version` 是 2；导入旧的 v1 备份（没有箱子层）时会按型号自动整理成箱子。

## 六、模式一：扫码建卡板

### 现场作业结构

```
卡板 P001（一板 50~60 箱）
├─ 箱 B001（型号 M-100，约 20 条条码）
│   ├─ 条码 SN-000001
│   ├─ 条码 SN-000002
│   └─ …（约 20 条）
├─ 箱 B002（型号 M-200 ← 每加一箱都要重新扫型号）
│   └─ …
└─ …（装满 50~60 箱）
顺序：加箱子（扫型号）→ 扫这一箱的条码 → 封箱 → 一板装满 → 封板
```

### 操作步骤

1. 首页「扫码建板」→「新建任务」（可填任务名，选择每板 50 / 55 / 60 箱，默认 60）。
2. 自动创建 `P001`，显示「0/60 箱」，并提示**先添加箱子**。
3. 点 **＋ 添加箱子** → 弹出窗口里**扫/输这一箱的型号**（例如 `M-100`）→  
   点「**确认并开始扫条码**」。每个箱子的型号都可能不同，所以**每加一箱都要重新扫一次**。
4. 点**开始扫描**调起摄像头 → 对准这一箱里的条码逐个扫：
   - 新条码 → 记入当前箱，提示「已记录 SN-000001（B001 第 3 条）」；
   - **重复条码 → 只提示「条码重复」，不计数**（一件物品一个条码，重复说明扫重了）；
   - 每次成功：**双短音 + 震动 + 顶部提示**，界面**不滚动、不跳转**，可以一直扫。
5. **封箱**：这一箱扫完（约 20 条）点「封箱 B001」→ 二次确认 → 该箱置为「已封箱」。  
   没封箱时**不允许加下一个箱子**（避免漏封）。
6. 重复第 3~5 步装箱，直到本板 60 箱：达到上限后按钮会禁用并提示「本板已满，请封板」。
7. **封板**：二次确认 → **自动导出本板 Excel** → 自动创建 `P002`，继续下一板。
8. **结束本次任务**：二次确认 → 导出总 Excel，任务可随时重新打开继续扫。

### 其它操作

- **撤销上一条**：撤销最近扫的那一条条码。
- 展开某个箱子（点箱号行）可以看到这一箱的条码明细，并能**删除单条**或**删除整箱**。
- **一键删除重复**：扫重留下的重复条码，每个条码保留最早一条，一键清理（按钮只在有重复时出现）。
- **手动输入**：条码枪或粘贴清单（每行一个），全部记到当前箱。
- **继续扫这一箱**：已封的箱可以点开查看，但不能再往里扫（要改就先删掉整箱重扫）。

### 单板 Excel 格式

| 卡板号  | 箱号   | 箱序号 | 条码        | 箱内序号 | 型号    | 数量 | 扫描时间                | 备注 |
| ---- | ---- | --- | --------- | ---- | ----- | -- | ------------------- | -- |
| P001 | B001 | 1   | SN-000001 | 1    | M-100 | 1  | 2025-01-01 09:00:00 |    |
| P001 | B001 | 1   | SN-000002 | 2    | M-100 | 1  | 2025-01-01 09:00:20 |    |
| P001 | B002 | 2   | SN-000010 | 1    | M-200 | 1  | 2025-01-01 09:02:00 |    |

底部汇总行：`汇总 | 箱数 | 2 | 条码数 | 3 | 型号数 | 2`，以及任务名与封板时间。

### 总 Excel 格式（4 个 Sheet）

- **Sheet1 总览**：任务名、状态、创建/更新时间、卡板数、已封板数、**总箱数、总条码数**、不同条码数、  
  每板箱数上限，以及「条码 / 型号 / 数量 / 出现卡板数」明细。
- **Sheet2 卡板汇总**：卡板号、状态、**箱数、条码数**、不同条码数、型号、各条码数量明细（`条码×数量`，按数量降序）、创建时间、封板时间。
- **Sheet3 箱汇总**：卡板号、箱号、箱序号、型号、条码数、状态（扫码中/已封箱）、创建时间、封箱时间、备注。
- **Sheet4 条码明细**：与单板表同结构（一物一行）。

> 这张「总表」就是模式二的输入，直接导入即可。

## 七、模式二：按货单配卡板

1. 「按单配板」→ **① 导入货单 Excel** → **② 导入模式一 Excel**  
   （也可以直接点「使用当前任务的扫描数据」，不用导文件）。
2. 设置每板箱数上限（50/55/60）与**每层箱数**（用于算层号，默认 5）。
3. 点 **③ 开始配板**，结果分三块展示：
   - 统计：卡板数、已配箱数、货单总箱数、拆分板数、未匹配、数量差异；
   - 每个卡板的**堆放顺序（底层 → 顶层）**，点进去看逐箱明细与层号；
   - 异常列表（未匹配 / 数量差异 / 条码冲突 / 超限拆分）。
4. **导出配货 Excel**（3 个 Sheet）。

颜色约定：已匹配=绿（`#16a34a`）、未匹配=红（`#dc2626`）、  
数量差异=黄（`#d97706`）、超限拆分=橙（`#ea580c`）。

### 配板规则（实现细节）

1. **编号 → 主卡板映射**：统计模式一中每个编号在各卡板的数量，  
   取**数量最多的卡板**；数量相同时取**最早出现**的卡板；同一编号出现在多个卡板时在异常里提示冲突。
2. **一件一行**：货单的「数量」按件数展开（数量 3 → 3 件，分别算层号与堆放顺序）。
3. **同编号优先同板**：按映射把货单条目分到对应卡板。某个编号的整批在当前卡板里放不下时，  
   **先折一块新卡板**（新卡板号从 `P001` 起顺延，自动跳过已占用的号），让这个编号整批连续；  
   如果这批本身就超过每板上限，则逐板填满（此时该编号必然跨板，且会记录拆分）。  
   折板不会产生空卡板（这一点有专门的回归用例）。
4. **卡板内排序**：按该板内每个编号的**数量降序**（多的在底层）；数量相同按**货单原始顺序**，  
   再按编号字典序。同编号的件连续堆放，不会被别的编号插队。
5. **层号 layerIndex**：每层最多「每层箱数」箱（默认 5），层内保持编号连续；  
   层按数量从多到少**从下往上**排，`layerIndex = 1` 是最底层，数字越大越靠上。
6. **异常**：货单有编号但模式一没有 → `unmatched`（单独放在「未匹配」卡板并标红，不混入正常卡板）；  
   货单数量与模式一数量不同 → `qty_mismatch`（按货单数量配货，并提示差异）；  
   超限拆分 → `overflow_split`；同编号多卡板 → `conflict`。

### 配货 Excel 格式

- **Sheet1 配货总览**：生成时间、货单文件、模式一文件、每板上限、每层箱数、各种统计，  
  再来一张表：卡板号、总箱数、编号种数、层数、**底层→顶层编号顺序摘要**、是否拆分、来源卡板。
- **Sheet2 配货明细**：卡板号、**堆放顺序**、**层号(1=最底)**、层内顺序、条码/编号、数量、名称、备注，最后一行合计。
- **Sheet3 异常**：异常类型（未匹配/数量差异/编号冲突/超限拆分）、编号、名称、卡板号、货单数量、模式一数量、说明；  
  下方附「卡板超限拆分记录」（原卡板、新卡板、涉及箱数、说明）。

**注意事项**

- 编号建议存成**文本**：Excel 会把 13 位以上数字变成科学计数法（`6.9E+12`），
  可在单元格前加英文单引号 `'`，或先把列格式设为「文本」。
- 数量列写 `1`、`12` 或 `12 箱` 都能识别（会自动取数字）。
- 「合计/汇总/总计/小计」开头的行会被自动跳过，不会当成数据。
- 「不同编号数」「总箱数」这类统计列不会被误当成编号/数量列。

## 十一之二、部署（GitHub + Cloudflare Pages）

### 1. 代码仓库

- GitHub：<https://github.com/QWQFuLan/pallet-scan>

  以及 **`certs/`（证书私钥不上传）**。

```bash
git add -A
git commit -m "说明"
git push
```

### 2. Cloudflare Pages（自动发版，推荐）

1. 打开 Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**
2. 选择仓库 `QWQFuLan/pallet-scan`，分支 `main`
3. 构建设置：
   - Framework preset：`None`
   - Build command：`npm run build`
   - Build output directory：`dist`
4. 保存后每次 `git push` 都会自动重新部署。线上地址：<https://pallet-scan.pages.dev>

### 3. Cloudflare Pages（命令行部署）

```bash
npx wrangler login          # 首次登录
npm run deploy              # = npm run build && wrangler pages deploy dist --project-name=pallet-scan
npm run test:deployed       # 部署完跑一遍线上自检
```

仓库里的 `wrangler.toml` 已写好项目名与输出目录；`public/_headers` 会一并发布，
设置了 HSTS、`Permissions-Policy: camera=(self)`（摄像头只允许本站使用）和静态资源长缓存。

> ⚠️ **不要放 `public/_redirects`**：实测在 Cloudflare Pages 上会导致
> `Failed to publish your Function. Got error: Unknown internal error occurred.`
> 本应用是单页且入口就是 `/`，本来也不需要 SPA 回落规则。

### 4. 线上环境的注意事项

线上站点虽然是公网地址，但**数据依然只存在每台手机的浏览器里**（IndexedDB），
不会上传到 Cloudflare 或任何服务器 —— 服务器只负责把静态文件发给你。
要跨设备搬数据，用「数据导出」里的 JSON 备份文件。

另外 Cloudflare 的域名是 **https**，所以手机直接就能用摄像头（不需要自签证书那套流程）。

## 十三、常见问题

**Q：`npm install` 报 EPERM / 权限错误？**
项目内的 `.npmrc` 已把 npm 缓存指向 `./.npm-cache`，避免系统缓存目录权限问题。若仍失败，删除
`node_modules` 与 `.npm-cache` 后重试，或用管理员身份的终端。

**Q：手机打开只有一片纯色（蓝色/白色）或一直转圈？**
程序**不会再留一片空白**：只要加载或运行出错，页面会直接显示「⚠️ 程序启动失败」并把错误内容印出来，
截图发出来即可定位。看到这个错误页时，按里面列的三条原因处理（浏览器太旧 / 用了 http / 无痕模式）。

如果**连错误页都没有**（页面真的全空），基本是手机浏览器缓存了旧版本的 js：
1. **Chrome（安卓）**：地址栏左侧锁图标 → 「Cookie 和网站数据」→ 清除 → 刷新；或直接用无痕窗口打开。
2. **Safari（iOS）**：设置 → Safari → 高级 → 网站数据 → 删除该网站；或用无痕标签页打开。
3. 也可以**换个端口**绕开缓存：`npm run dev -- --port 5180`，手机访问新端口。
4. 确认地址是 `https://` 开头（用 http 打开时摄像头会被浏览器禁用）。

**Q：电脑能开、iPad 能用，就某台手机不行？**
多半是那台手机的浏览器内核太旧（需要 Chrome 80+ / iOS 14+ 这一级别）。
先看错误页确认原因；确实是旧内核就换最新版 Chrome/Edge。

**Q：添加箱子时想用手机扫型号，怎么扫？**
「添加箱子」弹窗里**自带摄像头面板**：点弹窗里的「开始扫描」，对着型号条码扫一下，
扫到的型号会自动填进型号输入框，再点「确认并开始扫条码」。摄像头不可用时直接手动输入型号也可以。

**Q：手机提示 `NotFoundError: The object can not be found here.` 或摄像头打不开？**
这是 `getUserMedia`（打开摄像头）失败。程序现在会**自动逐级降级**（指定摄像头 → 后置摄像头 →
默认分辨率 → 浏览器默认），并把**真实原因**显示在预览区里，不再只弹一句英文错误。按提示处理：

| 界面提示 | 处理办法 |
| --- | --- |
| 权限被拒绝 | 地址栏锁图标 → 允许摄像头；确认是 `https://` 打开 |
| 没有找到可用摄像头 | 关掉占用相机的应用（相机、微信视频等）；去「设置 → 摄像头 → 测试摄像头」看真实结果 |
| 摄像头被其他应用占用 | 关掉相机/微信等，再点一次「开始扫描」 |
| 启动被中断 | 再点一次「开始扫描」（面板上有「重试打开摄像头」按钮） |
| 不是安全上下文 | 必须用 `https://电脑IP:5173`，不能用 `http://` |

另外程序**不再自动记住某个摄像头 id** —— 那个 id 换手机或系统更新后会失效，正是这个报错的常见原因。
需要固定摄像头时，在「设置 → 摄像头」里手动选择；旁边的「测试摄像头」会直接告诉你当前能不能用、
用的是哪个设备、什么分辨率。

**Q：手机打开是白屏？**
确认用的是 `https://` 且端口没被防火墙拦（Windows 防火墙放行 Node.js）。
电脑上先自测 `https://localhost:5173` 能打开。

**Q：扫码识别不出来？**
设置页会显示当前识别引擎（`原生识别` 或 `ZXing 识别`）。原生识别更快（Android Chrome）。
识别困难时：拉近一点让条码占画面 1/3 以上、避免反光和褶皱、把条码贴在镜头正前方
（一维码对水平方向敏感，可稍微旋转手机）。实在不稳定就用「手动输入」或条码枪。

**Q：一板扫到 60 箱还想继续扫？**
先封板会自动开新板。也可以在设置里把每板箱数上限改成 50/55/60（当前任务同步生效）。
注意：一板装满（达到上限）后**必须先封板**才能继续加箱子。

**Q：模式二提示「未匹配」怎么办？**
说明货单里的条码在模式一数据里不存在。检查条码是否被 Excel 转成了科学计数法，
或用 Excel 的 `VLOOKUP`/筛选对比两边条码。未匹配的条码会单独放在「未匹配」卡板并标红，不会混入正常卡板。

**Q：想一次管很多天的任务？**
每个任务独立保存，在「数据导出 → 历史任务」里随时打开或删除；也可以导出 JSON 归档。

**Q：数据存在哪里？怎么彻底删除？**
浏览器 IndexedDB（数据库名 `pallet-scan`）。
「数据导出 → 清空全部数据」即可删除；也可以清除该站点的浏览器数据。
